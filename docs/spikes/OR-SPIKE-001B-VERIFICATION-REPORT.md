## 一、背景

OpportunityRadar V0 的核心能力之一是：根据商业研究目标，自动从抖音 Web 批量获取与关键词相关的视频和账号候选数据。

OR-SPIKE-001 已验证 Feed 采集可用（100% 提取成功率，100% URL 可追溯），但 Feed 内容非关键词相关。本工作包（OR-SPIKE-001B）的目标是验证：**人工登录后，系统能否稳定完成真正的关键词搜索**。

## 三、测试过程与结果

### 3.1 第一轮：Feed 采集（已通过）

运行 `--feed-only` 模式，连续 3 次成功采集 48-49 条视频/次。

| 指标 | Run 1 | Run 2 | Run 3 |
|------|-------|-------|-------|
| Raw | 48 | 49 | 49 |
| Unique Videos | 48 | 49 | 49 |
| Extraction Success | 100% | 100% | 100% |
| Traceable URL | 100% | 100% | 100% |

**结论**：Feed 采集稳定可用，但内容为抖音推荐算法生成，与商业关键词无关。

### 3.2 第二轮：搜索登录检测

运行 `--use-search` 模式，系统正确检测到登录覆盖层：

```
LOGIN REQUIRED
Douyin requires login to access search results.
Please complete login in the browser window.
(扫码登录 / 验证码登录 / 密码登录)
Waiting up to 120 seconds...
```

**发现**：搜索页面有一个 z-index 9999 的登录覆盖层（"登录后即可搜索更多精彩视频"），与首页的 `login-full-panel` 不同，需要新的检测逻辑。

### 3.3 第三轮：人工扫码登录

用户在 Playwright 浏览器中完成扫码登录，系统检测到登录完成并继续执行。

**但搜索结果没有加载**。系统尝试滚动触发和重新提交搜索，均未成功。

### 3.4 第四轮：验证码拦截

再次运行时，系统检测到验证码（`#captcha_container`）：

```
CAPTCHA REQUIRED
Douyin is showing a captcha challenge.
Please solve it in the browser window.
Waiting up to 180 seconds...
```

用户解决验证码后，系统继续检测到登录覆盖层，再次登录后继续执行。

### 3.5 第五轮：成功采集但数据来源错误

本次成功采集到 7 条视频，但存在严重问题：

| 字段 | 预期值 | 实际值 | 问题 |
|------|--------|--------|------|
| collection_mode | search | search | ✅ 正确 |
| source_query | 短视频代运营 | 短视频代运营 | ✅ 正确 |
| source_page_url | https://www.douyin.com/search/... | https://www.douyin.com/user/self?from_tab_name=main | ❌ **错误** |
| title | 与代运营相关 | "注册入学的考生们..." | ❌ **无关** |
| author | 真实作者 | @抖音热点 / null | ❌ **部分缺失** |

**根本问题**：登录后页面跳转到了用户主页（`/user/self`），提取的是用户主页的 Feed 数据，不是搜索结果。但 `collection_mode` 被错误标记为 `search`。

### 3.6 第六轮：修复后验证

添加了页面 URL 验证（`/search/` 必须在 URL 中），但此时抖音已经开始拦截：

```
Search results did not load for query: 短视频代运营
```

连续多次运行均无法加载搜索结果。

### 3.7 第七轮：完全被拦截

再次运行，系统被抖音完全拦截，搜索页面无法加载任何内容。

**用户反馈**："应该是被抖音检测到了，现在一直被拦截"。

## 四、核心问题分析

### 4.1 问题 1：抖音反自动化检测

**现象**：
- 多次尝试登录后，抖音开始频繁弹出验证码
- 最终完全阻断搜索页面访问
- 即使登录成功，搜索结果也无法加载

**原因**：
- Playwright Chromium 的浏览器指纹与真实用户浏览器不同
- 频繁的自动化访问行为触发了抖音的风控系统
- 抖音对搜索功能的保护比 Feed 更严格

**影响**：搜索功能无法在无人值守情况下稳定使用。

### 4.2 问题 2：登录后页面跳转

**现象**：
- 用户在搜索页面扫码登录后，页面自动跳转到用户主页（`/user/self`）
- 提取的数据实际来自用户主页的 Feed，不是搜索结果

**原因**：
- 抖音的登录流程可能会重定向到用户主页
- 系统没有验证登录后是否仍然在搜索页面

**影响**：数据来源不可靠，无法证明采集的是搜索结果。

### 4.3 问题 3：搜索结果渲染不稳定

**现象**：
- 有时搜索结果可以渲染（诊断期间捕获了 18 条结果）
- 有时搜索结果完全不渲染
- 渲染时使用的是 `div.search-result-card` 元素，但其中没有视频 URL

**原因**：
- 抖音搜索结果是动态加载的，依赖 JavaScript API 调用
- 搜索卡片中没有 `/video/` 链接或视频 ID
- 视频身份信息可能只在点击后才会暴露

**影响**：即使搜索结果渲染，也无法获取视频 URL 进行追溯。

### 4.4 问题 4：数据来源混淆

**现象**：
- 系统标记为 `search` 的数据实际来自用户主页 Feed
- `source_page_url` 记录的是提取时的页面 URL，不是搜索页面 URL

**原因**：
- `collection_mode` 是基于采集意图设置的，不是基于实际数据来源
- `source_page_url` 在提取时才记录，此时页面可能已经跳转

**影响**：数据溯源链断裂，无法证明数据与关键词搜索的关联性。

## 五、技术发现

### 5.1 抖音搜索页面结构

| 元素 | 说明 |
|------|------|
| `div.search-result-card` | 搜索结果卡片容器 |
| 卡片文本格式 | `[duration][view_count][title] [@author] · [date]` |
| 视频链接 | **不在 DOM 中** |
| 视频 ID | **不在 DOM 中** |
| 登录覆盖层 | z-index 9999，文本"登录后即可搜索更多精彩视频" |
| 验证码容器 | `#captcha_container`（iframe） |

### 5.2 抖音反检测机制

| 机制 | 触发条件 | 表现 |
|------|----------|------|
| 登录覆盖层 | 未登录访问搜索页 | 弹出登录窗口，阻挡所有交互 |
| 验证码 | 频繁访问或检测到自动化 | 弹出滑块/点选验证码 |
| 页面跳转 | 登录后 | 可能跳转到用户主页 |
| 完全拦截 | 多次触发风控 | 搜索页面无法加载任何内容 |

### 5.3 已验证的代码能力

| 能力 | 状态 | 说明 |
|------|------|------|

| 登录检测 | ✅ 可用 | 正确识别登录覆盖层 |
| 验证码检测 | ✅ 可用 | 正确识别验证码容器 |
| 人工登录等待 | ✅ 可用 | 系统暂停并提示用户 |
| 搜索结果解析 | ⚠️ 部分可用 | 可解析卡片文本，但无视频 URL |
| 搜索来源验证 | ❌ 不可用 | 无法稳定获取搜索结果 |

## 六、失败原因总结

1. **抖音反自动化检测**：Playwright Chromium 的指纹被识别，多次访问后触发风控
2. **登录后页面跳转**：登录后页面自动跳转到用户主页，不在搜索结果页
3. **搜索结果渲染不稳定**：有时渲染有时不渲染，行为不可预测
4. **视频身份缺失**：搜索卡片中没有视频 URL 或 ID，无法追溯
5. **数据来源混淆**：无法区分搜索结果和 Feed 内容

## 九、建议的备选方案

### 方案 A：人工辅助模式
- 用户手动登录抖音
- 手动导出搜索结果的 URL 列表
- 系统批量访问 URL 并提取视频元数据
- **优点**：绕过搜索页面的反自动化检测
- **缺点**：需要人工操作，无法完全自动化

### 方案 B：Feed + 关键词过滤
- 继续使用 Feed 采集（已验证可用）
- 基于标题/描述文本匹配关键词
- **优点**：完全自动化
- **缺点**：Feed 内容由推荐算法生成，与关键词相关性低

### 方案 C：其他数据源
- 小红书、快手、B站等平台
- 部分平台的反检测机制可能较弱
- **优点**：可能更容易采集
- **缺点**：需要重新开发适配器

### 方案 D：降低采集频率
- 大幅降低搜索请求频率（如每小时 1 次）
- 使用代理池分散请求
- **优点**：可能避免触发风控
- **缺点**：仍然可能被检测，且数据时效性差
